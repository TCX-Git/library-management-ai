## 1. 项目目标

### 1.1 项目背景
本项目是《软件设计与体系结构》课程实验项目，用于训练需求分析、UML 建模、架构设计、数据库设计、详细设计与代码实现能力。

### 1.2 建设目标
开发一个基于 B/S 架构的图书管理系统，支持读者注册、借阅证管理、图书标题与馆藏副本维护、图书借阅、图书归还、借阅查询、图书预约、超期罚款计算与缴纳，以及借阅/罚款规则的维护。

### 1.3 范围说明
系统聚焦核心借阅流程：注册、借阅、归还、预约、罚款。不实现统计报表、读者信用评级等扩展功能；不实现真实支付扣款、条码扫描硬件、复杂全文检索、多校区馆藏调拨、微信或统一身份认证登录（详见第 9 章）。

## 3. 功能需求

> 每个功能需求包含：描述、执行角色、验收标准（触发场景 → 预期行为）。

### FR-001 注册读者账号

**描述**：读者不能自助注册。账号由图书管理员创建，必填信息为姓名、学号/工号、身份类型、联系方式。注册后账号默认"待激活"，管理员审核通过后方可借阅。

**执行角色**：图书管理员。

**验收标准**：
1. 管理员提交完整合法的必填信息 → 系统创建账号，状态置为"待激活"，返回成功。
2. 缺少任一必填信息（姓名/学号工号/身份类型/联系方式） → 系统拒绝创建，并提示具体缺失项。
3. 学号/工号已存在 → 系统拒绝创建，并提示"已存在该学号/工号"。
4. 管理员对"待激活"账号执行审核通过 → 账号状态变为"已激活"，读者获得借阅资格。
5. 读者或未登录用户尝试注册 → 系统拒绝（越权）。

---

### FR-002 办理借阅证

**描述**：管理员为已激活且尚无借阅证的读者办理借阅证。账号、读者、借阅证三者为一对一关系，一个读者只能持有一张借阅证。

**执行角色**：图书管理员。

**验收标准**：
1. 对已激活且无借阅证的读者办理 → 系统生成唯一借阅证号，借阅证状态置为"有效"。
2. 对已有有效借阅证的读者再次办理 → 系统拒绝，并提示"该读者已有借阅证"。
3. 对"待激活"或无效账号办理 → 系统拒绝，并提示需先激活账号。

---

### FR-003 删除借阅证

**描述**：管理员注销（删除）读者借阅证，借阅证状态置为"已失效"，保留历史记录，不删除读者数据。

**执行角色**：图书管理员。

**验收标准**：
1. 读者无未还图书且无未缴罚款时删除 → 借阅证状态置为"已失效"，保留读者历史数据，返回成功。
2. 读者存在未还图书或未缴罚款时删除 → 系统拒绝，并提示需先处理未还图书或欠费。
3. 借阅证删除后，该读者发起借阅或预约 → 系统拒绝（借阅证无效）。

---

### FR-004 添加图书管理员

**描述**：由超级管理员创建图书管理员账号。

**执行角色**：初始超级管理员。

**验收标准**：
1. 超级管理员提交合法信息 → 系统创建管理员账号，该账号可登录并执行管理操作。
2. 重复的管理员账号标识 → 系统拒绝创建。
3. 非超级管理员账号执行创建 → 系统拒绝（越权）。

---

### FR-005 删除图书管理员

**描述**：由超级管理员停用（删除）图书管理员账号。

**执行角色**：初始超级管理员。

**验收标准**：
1. 停用管理员账号后 → 该账号无法再登录、无法执行任何管理操作。
2. 尝试停用最后一个超级管理员（默认管理员） → 系统拒绝，防止系统失去唯一管理员入口。
3. 非超级管理员执行删除 → 系统拒绝（越权）。

---

### FR-006 添加图书标题信息

**描述**：管理员录入图书标题信息，字段包括题名、作者、ISBN、分类号、出版社、出版年。

**执行角色**：图书管理员。

**验收标准**：
1. 提交完整合法信息 → 系统创建图书标题记录，返回成功。
2. ISBN 已存在 → 系统拒绝，并提示"该 ISBN 已存在"。
3. 缺少必填字段（题名/ISBN） → 系统拒绝，并提示缺失字段。

---

### FR-007 删除图书标题信息

**描述**：管理员删除图书标题信息。

**执行角色**：图书管理员。

**验收标准**：
1. 标题无关联馆藏副本 → 系统删除标题记录成功。
2. 标题存在关联馆藏副本（含在架、借出、预约保留等任意状态） → 系统拒绝删除，并提示需先处理关联副本。
3. 删除后，按该标题查询 → 系统不再返回该标题。

---

### FR-008 添加馆藏副本

**描述**：管理员为某图书标题添加馆藏副本，字段包括副本号、馆藏位置，副本初始状态为"在架"。

**执行角色**：图书管理员。

**验收标准**：
1. 标题存在时添加 → 系统创建副本，副本号唯一，状态为"在架"。
2. 标题不存在时添加 → 系统拒绝，并提示"标题不存在"。
3. 副本号在同一标题下重复 → 系统拒绝，并提示"副本号重复"。

---

### FR-009 删除馆藏副本

**描述**：管理员删除馆藏副本。

**执行角色**：图书管理员。

**验收标准**：
1. 副本状态为"在架"或"维护中"且无关联借阅记录 → 系统删除副本成功。
2. 副本状态为"借出"或"预约保留" → 系统拒绝删除。
3. 删除后按副本号查询 → 系统不再返回该副本。

---

### FR-010 查询图书

**描述**：读者和管理员可按题名、作者、ISBN、分类号等条件查询图书标题及其副本状态。

**执行角色**：读者、图书管理员。

**验收标准**：
1. 按题名模糊查询 → 系统返回匹配的标题列表及各副本可借状态（在架/借出/预约保留/维护中/丢失）。
2. 无匹配结果 → 系统返回空列表。
3. 各副本状态显示与实际一致。

---

### FR-011 借阅图书

**描述**：管理员为读者办理图书借阅。借阅前必须通过前置校验（见 BR-007），通过后副本状态置为"借出"，记录应还日期。

**执行角色**：图书管理员。

**验收标准**：
1. 前置条件全部满足 → 借阅成功，副本状态置为"借出"，读者借阅列表增加该副本，应还日期按读者类型与借出物类型计算（见 BR-001、BR-003）。
2. 借阅证无效 → 系统拒绝，并提示"借阅证无效"。
3. 当前借阅数已达上限 → 系统拒绝，并提示"已达借阅上限"。
4. 读者存在超期未还 → 系统拒绝，并提示"存在超期未还"。
5. 读者存在未缴罚款 → 系统拒绝，并提示"存在未缴罚款"。
6. 读者已借同一标题的副本 → 系统拒绝，并提示"同标题限借 1 本"。
7. 目标副本已被他人借出或并发冲突 → 系统拒绝，并提示"副本不可借"。

---

### FR-012 归还图书

**描述**：管理员为读者办理归还。若产生超期罚款，归还先完成，罚款记入读者欠费（挂账，见 BR-010）。

**执行角色**：图书管理员。

**验收标准**：
1. 未超期归还 → 副本状态置为"在架"，借阅记录标记为已归还，读者借阅数减一。
2. 超期归还 → 归还操作完成，系统按规则计算罚款并记入读者欠费，副本状态置为"在架"。
3. 归还后，读者借阅列表中该副本消失。

---

### FR-013 查询借阅信息

**描述**：读者查询本人借阅信息；管理员查询任意读者的借阅信息。

**执行角色**：读者、图书管理员。

**验收标准**：
1. 读者查询本人 → 返回当前借阅列表、借阅历史、未缴罚款、预约状态。
2. 读者查询其他读者 → 系统拒绝（越权）。
3. 管理员查询任意读者 → 返回该读者完整的当前借阅、历史借阅、罚款、预约信息。

---

### FR-014 预约图书

**描述**：当某标题所有副本均被借出时，读者可发起预约，进入等待队列；副本释放后系统按优先级与先到先得分配，并通知读者。

**执行角色**：读者（发起）、图书管理员（处理分配）。

**验收标准**：
1. 该标题所有副本均被借出、读者未借该标题且未达预约上限 → 预约成功，进入预约队列。
2. 读者已借该标题 → 系统拒绝预约，并提示"已借该标题不可预约"。
3. 读者预约数已达上限（3 个） → 系统拒绝，并提示"预约数量已达上限"。
4. 读者存在未缴罚款 → 系统拒绝，并提示"存在未缴罚款"。
5. 副本释放时 → 系统按优先级（教师 > 博士生 > 研究生 > 本科生 > 专科生）分配，同级按先到先得；分配后副本状态置为"预约保留"，并向读者发送站内消息。

---

### FR-015 计算超期罚款

**描述**：系统按借出物类型单价 × 超期天数计算罚款，单册罚款金额有上限。

**执行角色**：系统自动。

**验收标准**：
1. 中文图书超期 N 天 → 罚款 = min(0.1 × N, 20) 元。
2. 外文图书超期 N 天 → 罚款 = min(0.2 × N, 20) 元。
3. 杂志超期 N 天 → 罚款 = min(0.5 × N, 20) 元。
4. 论文超期 N 天 → 罚款 = min(1.0 × N, 20) 元。
5. 未超期（N ≤ 0） → 罚款为 0。
6. 罚款累计达到单册上限（20 元） → 不再累加。

---

### FR-016 维护借阅规则和罚款规则

**描述**：管理员维护读者类型借阅上限与期限、借出物类型限制、罚款单价与上限。

**执行角色**：图书管理员。

**验收标准**：
1. 管理员修改某读者类型借阅数量上限 → 保存后新发生的借阅按新规则执行。
2. 管理员修改某借出物类型罚款单价 → 保存后新产生的罚款按新单价计算。
3. 输入非法值（如负数上限、负数单价） → 系统拒绝保存并提示。
4. 非管理员执行维护 → 系统拒绝（越权）。

---

### FR-017 续借图书（补充）

**描述**：读者在借图书可申请续借，限续借 1 次，续借期限与原期限相同。

**执行角色**：图书管理员（办理）。

**验收标准**：
1. 未超期、无欠费、且该副本未续借过 → 续借成功，应还日期顺延原期限。
2. 该副本已续借过 1 次 → 系统拒绝，并提示"不可再次续借"。
3. 借出物为论文 → 系统拒绝，并提示"论文不可续借"。
4. 读者存在超期未还或未缴罚款 → 系统拒绝续借。

---

### FR-018 标记罚款已缴（补充）

**描述**：管理员线下收取罚款后，在系统中执行"标记已缴"操作（模拟缴费）。

**执行角色**：图书管理员。

**验收标准**：
1. 管理员对欠费读者执行"标记已缴" → 读者欠费状态清零，保留缴费历史记录。
2. 缴清后，读者恢复借阅与预约资格。
3. 非管理员执行标记 → 系统拒绝（越权）。

## 4. 业务规则

### BR-001 读者类型借阅限额

不同读者类型具有不同的可借数量上限与借阅期限：

| 读者类型 | 可借数量上限 | 借阅期限 |
| --- | --- | --- |
| 专科生 | 3 本 | 30 天 |
| 本科生 | 5 本 | 30 天 |
| 研究生 | 8 本 | 60 天 |
| 博士生 | 10 本 | 60 天 |
| 教师 | 15 本 | 90 天 |

验收条件：为某类型读者办理借阅时 → 应还日期 = 借阅日期 + 该类型期限；借阅数达该类型上限 → 拒绝借阅。

### BR-002 续借规则

所有读者类型均允许续借 1 次，每次续借期限与原期限相同；论文不可续借。

验收条件：续借成功 → 应还日期顺延一次原期限；已续借过 → 拒绝。

### BR-003 借出物类型借阅限制

| 借出物类型 | 限制 |
| --- | --- |
| 中文图书 | 正常（不额外限制） |
| 外文图书 | 数量限额减半、借阅期限减半 |
| 中文/外文杂志 | 仅短期借阅（7 天），不计入图书借阅限额 |
| 论文 | 仅短期借阅（3 天），不可续借 |

验收条件：借阅外文图书 → 限额与期限均按读者类型对应值减半；借阅杂志 → 期限固定 7 天且不占用图书限额。

### BR-004 借阅限额叠加规则

读者限额与借出物限额同时满足，取较小值（取严）。

验收条件：读者限额与借出物限额不一致时 → 以较小值为准判断是否达上限。

### BR-005 同标题副本借阅限制

同一读者不能同时借阅同一标题的多个副本，同一标题最多借 1 本。

验收条件：读者已借某标题副本，再借同标题另一副本 → 拒绝。

### BR-006 借阅证状态与有效性

借阅证状态包括"有效""已失效"。毕业生或离职教师借阅证自动置为"已失效"，保留历史记录，禁止新借阅和预约，但不删除数据。

验收条件：借阅证"已失效" → 借阅、预约均被拒绝。

### BR-007 借阅前置校验

借阅必须同时满足以下条件，否则禁止借阅：
1. 借阅证有效；
2. 当前借阅数未达上限；
3. 无超期未还；
4. 无未缴罚款。

验收条件：任一条件不满足 → 分别提示"证无效 / 已达上限 / 有超期 / 有欠费"并拒绝借阅。

### BR-008 超期罚款单价

| 借出物类型 | 单价 |
| --- | --- |
| 中文图书 | 0.1 元/天 |
| 外文图书 | 0.2 元/天 |
| 杂志 | 0.5 元/天 |
| 论文 | 1.0 元/天 |

验收条件：超期 N 天 → 罚款 = 单价 × N（不超过单册上限）。

### BR-009 罚款金额上限

单册罚款上限 20 元，达到上限不再累加；不产生滞纳金或复利。

验收条件：累计罚款 ≥ 20 元 → 按 20 元封顶，不再随时间增长。

### BR-010 罚款缴纳规则

归还时若产生罚款，允许挂账：归还先完成，罚款记入欠费；下次借阅时校验欠费并追缴，缴清后才能继续借阅。采用模拟缴费：管理员线下收款后执行"标记已缴"，缴清后保留历史记录、欠费状态清零。未缴清罚款时，禁止借阅和预约（仅提醒不强制）。

验收条件：存在未缴罚款 → 借阅、预约被拒绝；"标记已缴" → 欠费清零、恢复借阅预约资格。

### BR-011 预约触发条件

预约触发条件为"该标题所有副本均被借出"。

验收条件：标题存在"在架"副本 → 不可预约；所有副本均被借出 → 可预约。

### BR-012 预约数量上限与限制

每位读者同时预约上限 3 个；已借出该标题的读者不能再预约同标题。

验收条件：预约数达 3 个或已借该标题 → 拒绝预约。

### BR-013 预约优先级与分配顺序

预约优先级：教师 > 博士生 > 研究生 > 本科生 > 专科生；同一标题多人预约时，副本释放后按优先级分配，同级按先到先得。

验收条件：副本释放 → 按优先级从高到低分配，同级按预约时间先后分配。

### BR-014 预约通知与保留期限

预约成功后通过站内消息通知（不接短信/邮件）；预约保留期限 7 天，过期未取自动取消，不记违约。

验收条件：预约分配成功 → 发送站内消息；7 天内未取书 → 预约自动取消。

### BR-015 账号-读者-借阅证关系

账号 ↔ 读者：一对一；读者 ↔ 借阅证：一对一（一个读者一张证）。

验收条件：一个账号对应一个读者、一个读者对应一张借阅证；重复关联 → 拒绝。

### BR-016 历史记录保留规则

需保留：借阅历史、归还历史、罚款历史、预约历史、操作日志。历史数据不自动清理，支持按时间范围查询统计，可选按年归档。

验收条件：历史操作均可被查询、可追溯，不因业务结束而删除。

## 5. 非功能需求

### NFR-001 性能
- 核心查询接口（图书查询、借阅信息查询）响应时间上限：**待定**（建议 ≤ 2s，人工确认后定稿）。
- 借阅/归还办理响应时间上限：**待定**（建议 ≤ 3s，人工确认后定稿）。

### NFR-002 可靠性与并发
- 系统为 B/S 架构，需支持多用户并发访问。
- 借阅/预约等对同一副本的竞争操作必须具备并发控制（加锁或乐观锁），保证数据一致性。
- 借阅、归还操作应具备原子性，避免产生副本状态与借阅记录不一致。

### NFR-003 安全性
- 实现基于角色的访问控制（RBAC），后端在每个受保护接口强制校验权限，不得仅依赖前端隐藏按钮。
- 需要用户会话与登录态管理（Session 或 Token，见待确认问题 P-06）。
- 密码等敏感信息应加密存储（不存明文）。
- 管理员维护、借阅证办理、罚款标记等敏感操作应记录操作日志以供审计。

### NFR-004 可维护性
- 采用分层架构（表示层 / 业务层 / 数据访问层 / 实体层），依赖方向自上而下、不得逆向依赖；表示层采用 MVC 模式。
- 业务规则（借阅规则、罚款规则、预约规则、读者类型限额等）必须落在业务层（Service），严禁写入 Controller。
- 涉及多读者类型与多借出物类型组合的规则，应通过策略/规则对象或查询表实现，禁止在多个 Controller 中重复硬编码。
- 日志应可支持问题排查与操作审计。

### NFR-005 测试约束
- 测试框架：pytest；覆盖率目标 ≥ 70%。
- 区分单元测试与集成测试（端到端测试可选）；使用独立测试数据库（SQLite 内存库）。
- 核心用例必须有自动化测试：注册、办理借阅证、借阅、归还、查询借阅信息、预约、超期罚款计算、权限控制。
- 权限相关测试（越权访问被拒绝）为必测项；每条核心业务规则至少有一条断言用例。

### NFR-006 技术栈与兼容性
- 后端：FastAPI（Python）；前端：纯 HTML + 模板（Jinja2）；数据库：SQLite；ORM：SQLAlchemy。
- 交付物需包含：需求文档、UML 图（用例图/类图/时序图）、架构设计文档、数据库设计、源码、测试代码与报告、可运行演示。

## 6. 领域对象与数据约束

### 6.1 读者（Reader）
1. **读者编号**：唯一标识。
2. **姓名**：必填。
3. **联系方式**：手机或邮箱，必填。
4. **身份类型**：本科生 / 研究生 / 博士生 / 专科生 / 教师，必填。
5. **在校/在职状态**：用于判断借阅证是否应失效。

### 6.2 借阅证
1. **借阅证号**：唯一。
2. **状态**：有效 / 已失效。
3. **关联读者**：一对一。

### 6.3 图书标题（Title）
1. **题名**：必填。
2. **作者**：可选。
3. **ISBN**：唯一，必填。
4. **分类号**：可选。
5. **出版社**：可选。
6. **出版年**：可选。

### 6.4 馆藏副本（Copy）
1. **副本号**：同一标题下唯一。
2. **馆藏位置**：可选。
3. **状态**：在架 / 借出 / 预约保留 / 维护中 / 丢失。
4. **关联标题**：一个标题对应多个副本（1:N）。

### 6.5 借阅记录
1. **读者**：必填。
2. **副本**：必填。
3. **借阅日期**：必填。
4. **应还日期**：按读者类型与借出物类型计算。
5. **实际归还日期**：归还时填写。
6. **是否已续借**：标记续借次数（最多 1 次）。

### 6.6 预约记录
1. **读者**：必填。
2. **标题**：必填。
3. **预约时间**：用于同级先到先得排序。
4. **状态**：等待中 / 已分配 / 已取书 / 已取消 / 已过期。

### 6.7 罚款记录
1. **读者**：必填。
2. **金额**：按规则计算，单册上限 20 元。
3. **状态**：未缴 / 已缴。
4. **缴纳时间**：标记已缴时填写。

## 7. 领域术语

**读者（Reader）**
: 拥有借阅资格的用户，是学生读者与教师读者的抽象父类。

**学生读者（StudentReader）**
: 读者子类，细分为本科生、研究生、博士生、专科生。

**图书标题（Title）**
: 描述一种图书的书目信息（题名、作者、ISBN 等），不涉及具体物理册数。

**馆藏副本（Copy）**
: 图书标题下的具体物理馆藏册，拥有独立副本号与状态。

**借阅证**
: 读者借阅资格的凭证，与读者一对一，状态可为有效或已失效。

**挂账**
: 归还图书时产生的罚款先记录为欠费、不要求当场缴清，下次借阅时追缴的机制。

**预约保留**
: 副本释放后为预约读者保留、等待取书的状态，保留期 7 天。
